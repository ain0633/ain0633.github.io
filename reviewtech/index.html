02 — 문제 정의

쓸 말이 없어서가 아니라,
글로 다듬는 일이 번거로워 포기합니다.

후기를 쓰면 적립금을 주는데도 사람들은 포기한다. 느낀 점이 없어서가 아니다 — 한 줄짜리 감상을 몇 문단의 글로 늘리는 일이 귀찮아서다. 그래서 리뷰테크는 느낀 점 한 줄만 받는다. 나머지는 AI가 늘린다.

그런데 그 “늘리는 일”을 LLM에 한 번 호출로 시키면 문제가 생긴다. 예시도 검증도 없이 생성하면 모델은 자꾸 광고 문구처럼 정리하고, 정중하게 권유하고, “최고”를 남발한다. 사람이 쓴 리뷰처럼 읽히지 않으면 유저는 그대로 복사하지 못한다.

실제로 검수 LLM이 적발한 문장 —
“결론부터 말하면 완전 대만족이에요.”
reason: 정리 표현

같은 입력으로 예시 주입 없이 생성한 결과와 파이프라인을 통과한 결과를 나란히 두면 차이가 보인다. (아래는 실측 comparison 데이터 — 왼쪽은 프로덕션 폴백 경로와 동일한 단독 호출)

05 — 버그 해결 · 배포 · 출시

출시일에 서버가 죽으면 생기는 일

SSH 없이 프로덕션 장애를 복구하다

2026-09-18 · 출시 당일 전면 장애

출시 직후 앱이 전면 “Load failed”. 원인은 무인 보안 업데이트가 nginx를 재시작하는 틈에, 과거 실험의 잔재였던 root 계정 pm2 프로세스(nodeapp)가 80/443 포트를 선점한 것. 로컬에 SSH 키가 없는 상황 — GitHub Actions에 임시 진단 워크플로를 만들어 원격으로 조사하고, 같은 방식으로 복구했다.

nginx 죽음잔재 nodeapp이 80/443 선점 Actions 워크플로로 원격 진단pm2-root 정지·비활성nginx 재기동pm2 startup 등록으로 재발 방지

토스 웹뷰에서 뒤로가기가 세 번 씹히던 버그

심사 반려의 진짜 원인

입력 위저드가 단계마다 backEvent 핸들러를 쌓기만 하고 해제하지 않아, 위저드를 떠난 뒤에도 죽은 핸들러가 뒤로가기를 3~4회 삼켰다. 핸들러 해제 함수를 ref 배열에 모아 unmount에서 일괄 해제하는 것으로 수정. 웹 브라우저에선 재현되지 않고 토스 웹뷰에서만 드러나는 종류의 버그였다.

5b8d42c 위저드 백스택 누수 수정 + confirm() 의존 제거

배포는 지루할수록 좋다

CI/CD — push마다 lint·빌드·테스트, master 머지 시 자동 배포

GitHub Actions 2개 워크플로: ci.yml이 모든 push를 검증하고, deploy.yml이 master 반영을 Lightsail(nginx + pm2)에 배포한다. 수동 배포로 먼저 검증한 뒤 자동화를 켰고, SQLite는 pm2 cron으로 매일 VACUUM INTO 백업. 파이프라인 단위 테스트도 CI에 물려 있어 프롬프트를 고치다 회귀가 나면 머지 전에 잡힌다.

06 — 한계

숨기지 않는 것들

critique는 스킵될 수 있다

생성이 13초를 넘기면 critique를, 20초를 넘기면 revise를 건너뛰고 초안을 반환한다. 품질 단계가 응답 시간을 볼모로 잡지 않게 한 선택이지만, 운영 로그에서 실제로 스킵이 발생한다.

품질 판단이 LLM 하나에 의존한다

정량 평가셋이 없다. “AI 티”의 기준은 critique 프롬프트의 금지 패턴 목록이 전부이고, 이 페이지의 추적 통계도 표본 3회다(3회 중 2회 revise 발동).

외부 의존은 내가 통제할 수 없다

넉 달 사이 임베딩 모델(text-embedding-004 API 제거)과 검색 API(네이버 쇼핑 종료)를 강제로 교체당했다. 크롤 차단(403)은 우회하는 대신 공유텍스트·그라운딩·사진의 3중 폴백으로 설계를 바꿨다.

출시 전 전수 테스트 결과표 — 데이터 준비 중

8개 플랫폼 23개 링크 전수 테스트 기록은 저장소 밖에 있어 회수·재실행이 필요하다.
